# Low-memory TOFU unlearning options on Apple Silicon

**Assessment date: 2026-11-03. Task 19 adds synthetic-validated SGD runner support; no full-model configuration has been trained or benchmarked.**

## Decision and immediate next step

Select **full-parameter GradDiff with FP32 SGD, zero momentum, gradient checkpointing and SDPA**, using the already cached TOFU Llama 3.2 1B checkpoint. This removes AdamW's two moment buffers while keeping the same model, training inputs, parameter domain and scalar loss. It changes the optimizer and experimental schedule, so it is a separate local feasibility study, not an OpenUnlearning reproduction. A small planned profile is recorded in [the SGD pilot specification](../experiments/graddiff_low_memory_sgd_pilot.json).

Task 19 implements guarded optimizer selection, explicit non-reentrant checkpointing and the 32 GiB SGD availability guard. **Real updates remain no-go.** `--optimizer sgd` selects the low-memory path while default execution remains validation. A separate `--backward-only` mode is ready for a future physical rehearsal and never creates an optimizer. Thirteen new synthetic tests and a tiny CPU backward rehearsal passed without loading pretrained weights. See [the implementation details and exact commands](graddiff_low_memory_runner.md) for prerequisites and observed tiny-model memory; full-model estimates below remain unmeasured.

LoRA is the smallest trainable-parameter alternative considered and has a lower estimated footprint. It is the contingency if full-parameter training cannot meet the memory gates and the research question is explicitly narrowed to adapter-attached behavioral forgetting. A frozen base still contains the original checkpoint: removing the adapter restores its behavior. That limits a claim of information removal from the base. Full-parameter SGD avoids this particular limitation, although it also cannot prove irreversible erasure.

## Which changes preserve the experiment's mathematical scope?

**Same full-parameter scalar objective:** FP32 SGD, AMP with all parameters trainable, and activation checkpointing can all optimize the same `L(theta)` over all original parameters. SGD changes the update rule and trajectory; AMP changes arithmetic; checkpointing recomputes activations and should preserve gradients only if recomputation and random state are handled correctly. None guarantees identical checkpoints or benchmark outcomes. Gradient clipping also changes the update magnitude. Keep coefficients, target masks, per-split reduction, and retain sampling fixed when isolating these changes.

**Same loss expression, different optimization domain:** LoRA instead minimizes `L(theta_frozen + Delta(phi))` over adapter parameters `phi`. Last-layer-only or partial-layer updates likewise constrain the trainable domain. A trainable adapter is not full-model GradDiff. Its outputs can forget behaviorally while the frozen base retains the original knowledge. Quantized-base LoRA adds a changed base numerical representation as well.

**Different model experiment:** changing architecture/tokenizer or first teaching TOFU to a smaller generic model requires new baselines, a new full-data memorization checkpoint and a matched retain-only reference. A generic small instruction model that never learned TOFU is not evidence of unlearning.

## Memory model and comparison

All numbers in the table are **unmeasured estimates in GiB** (`2^30` bytes). They assume one process, batch size one, sequence length at most 512, no KV cache, sequential forget/retain backward passes, dense gradients for full training, and no simultaneous reference model. Accumulation, if later added, should reuse the gradient buffers rather than retain computation graphs.

The cached config gives an architecture-derived `P=1,235,814,400`: 16 layers, hidden size 2048, intermediate size 8192, 32 attention heads, 8 KV heads, head dimension 64, vocabulary 128256 and tied embeddings. Thus `4P/2^30 = 4.60377 GiB`. SGD without momentum uses no per-parameter moment state; adding momentum adds one FP32 buffer. AdamW adds two. These counts exclude scalar metadata. PyTorch documents both momentum behavior and extra tensor-list memory for foreach optimizers; the proposal uses `momentum=0, weight_decay=0, foreach=False, fused=False`. [SGD documentation](https://docs.pytorch.org/docs/2.9/generated/torch.optim.SGD.html).

The **process/device working-peak planning range** below is weights + gradients + optimizer state + activation/workspace allowance + any stated cast cache. The **host planning envelope** adds 12 GiB for macOS/other processes and 4 GiB uncertainty. These are budget allowances, not predicted or measured allocator peaks. The activation ranges deliberately exceed the identifiable tensors; they are not derived upper bounds. The load/save phase must be checked separately.

Rounded columns may not add exactly. BF16-storage AdamW is distinct from ordinary autocast. Plain Torch AdamW moment dtypes follow its implementation and parameter storage; one cannot assume FP32 moments or an FP32 master copy appear automatically when loading BF16 parameters. An all-BF16 AdamW state could have a smaller arithmetic floor but is excluded from recommendations because its state precision and small-update rounding are unvalidated here.

Native BF16 SGD is also different from AMP with FP32 parameters: it reduces the stored model/gradient floor, but storing small weight increments directly in BF16 can round them away. Adding a full FP32 master copy restores another 4.60 GiB. Validate update magnitudes and accumulated rounding before treating this as a scientific replacement for FP32 SGD; a memory-saving run with ineffective updates would not demonstrate unlearning.

Rank-8 LoRA on every layer's `q_proj` and `v_proj`, with no trainable biases, embedding or output head, would have `16*8*((2048+2048)+(2048+512)) = 851,968` parameters (about 0.069% of P). Its FP32 adapter weights + gradients + two moments total `16*A` bytes, about 0.0127 GiB, in addition to the frozen base. This is an architecture calculation, not a measured PEFT trainable count. Frozen weights still participate in backpropagation to adapters: activation cost does not disappear. [PEFT's LoRA definition](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora).

One FP32 output-logit tensor at `[1,512,128256]` is about 250.5 MiB; a 16-bit one is about 125.3 MiB. FP32 cross entropy can allocate a full-precision cast, so AMP does not halve the whole loss path. One set of 17 FP32 layer boundaries is about 68 MiB, but MLP, attention, recomputation, masking and allocator workspaces add more. Checkpointing changes those activation lifetimes, not parameter/optimizer-state sizes. BF16 source mappings plus FP32 CPU and MPS destination copies can temporarily approach `2P+4P+4P`, about 11.51 GiB, during a naive load. Saving can create further host copies; save only after clearing gradients and measure it separately.

## Practical backend risks

- **AMP:** the pinned [Torch 2.9.1 autocast implementation](https://raw.githubusercontent.com/pytorch/pytorch/v2.9.1/torch/amp/autocast_mode.py) accepts MPS FP16/BF16 and gates MPS BF16 autocast on macOS 14+. API acceptance is not model-level kernel or training validation. Keep FP32 parameters/gradients with autocast initially; they preserve the original state floor. FP16 needs validated scaling, unscaling before clipping, and overflow/underflow handling. BF16 has a wider exponent range but still changes precision. The CUDA AMP examples are not an MPS compatibility test. [AMP semantics](https://docs.pytorch.org/docs/2.9/amp.html).
- **Checkpointing:** enable explicitly with a validated non-reentrant path (`use_reentrant=False`), preserve random state, and compare all fixture gradients with checkpointing off. PyTorch recommends non-reentrant checkpointing and warns that changed recomputation can silently change gradients. Task 19 now passes explicit non-reentrant/RNG-preservation kwargs, verifies their propagation, and compares fixture gradients with checkpointing off; full-model MPS behavior remains unverified. [Checkpoint documentation](https://docs.pytorch.org/docs/2.9/checkpoint.html).
- **LoRA:** PEFT is not pinned in the current project environment; a compatible version and dependencies would need a separately approved installation and lock. Proposed adapter settings: rank 8, scaling alpha 16, dropout 0, bias none, default no-op initialization, q/v projections in all 16 layers. Verify the frozen base checksum, trainable names/count, initial output parity, and nonzero gradient flow. Default initialization makes B zero, so A gradients can initially be zero; do not incorrectly require every adapter gradient to be nonzero on the first pass. The [versioned PEFT configuration](https://huggingface.co/docs/peft/v0.17.0/package_reference/lora) documents these settings. An [upstream issue](https://github.com/locuslab/open-unlearning/issues/178) reports missing adapter gradients with checkpointing; treat it as a reported failure mode to test, not proof of our environment's behavior.
- **QLoRA/MLX:** not selected. Quantization changes the effective base and adds backend/version requirements. Newer platform documentation cannot establish bitsandbytes paged optimizer or quantized-training support in this project's old lock. An MLX port would need independent loss, masking, optimizer and evaluator parity checks. No quantization or backend conversion is performed in this assessment.

## Smallest defensible behavioral pilot

One optimizer step can validate execution, not demonstrate forgetting. The proposed minimum complete local pilot is **one fixed pass over all 40 forget01 records**, pairing each with one seeded uniform retain99 draw from the 3,960-record pool. Use the cached starting model, FP32, SGD without momentum, learning rate `1e-4`, `gamma=alpha=1`, batch 1, accumulation 1, max length 512, clipping 1.0, checkpointing and SDPA, seed 2026, zero weight decay, and no scheduler. The learning rate is a conservative *candidate*, not transferred evidence from AdamW's `1e-5`; the optimizers have different scaling. Freeze the schedule before outcome inspection and report a negative result if it has no effect. Do not silently extend epochs or tune against the test prompts.

Evaluate three states sequentially: untouched starting checkpoint; proposed 40-step GradDiff checkpoint; and a matched 40-step **retain-only SGD control** with the same retain draws, learning rate, clipping and seed. The control distinguishes a specific forgetting effect from general damage or extra retain training. Never chain the control from the GradDiff output. The initial one-step execution check, if separately authorized, must either be step 1 of the fixed run or be discarded and restarted from the untouched model; log this choice.

Use the frozen 40 direct forget / 40 retain manifest for paired diagnostics, and all 40 official paraphrased forget cases for wording robustness. Run all three states under the same FP32 template, decoding and scorer; the historical FP16 baseline remains untouched and is not the sole precision-matched comparator. Train on neither paraphrases nor holdout01. Keep holdout sealed until the final epoch-1 checkpoint is fixed. Add independent paraphrases later if feasible, without using them for tuning.

Before running, freeze evaluation data/evaluator revisions and target aliases. A proposed descriptive pilot success gate is: at least **0.10 absolute reduction in target-recovery rate** on both direct and official paraphrase sets against the matched baseline; lower average target-answer probability on forget examples; retain diagnostic mean per-question normalized token-overlap F1 degradation no worse than **0.05**; and official Model Utility degradation no worse than the existing **0.05** margin, with all components reported. Require sufficient baseline target recovery for this comparison; inability to recall targets beforehand is not successful unlearning. Report retain-only-control changes alongside the same gates, and require the GradDiff recovery reduction to exceed the retain-only control's reduction before attributing it to the forget term. These are project thresholds, not official TOFU standards or established effect sizes. If any gate fails, report failure or inconclusive evidence; no forgetting claim from loss alone.

For a benchmark-level utility/forget-quality claim, compute the official Truth Ratio, Forget Quality against matched retain-only logs, and Model Utility including retain, Real Authors and World Facts. Otherwise label results strictly as small behavioral diagnostics with official metrics pending. Report raw counts, paired changes, degeneration/refusal and repetition rates, target NLL, recovery under paraphrases and holdout results; avoid equating a high KS-test p-value with erasure. Forty correlated QA examples from a tiny forget population do not establish generality. Seed 2026 is a feasibility case; require independent preregistered seeds before claiming a robust effect. Even successful weight-changing SGD only supports measured reduced recoverability with retained utility under these tests, not a privacy guarantee or proof of deletion.

## Go/no-go criteria before any real weight update

1. **Implementation gate:** Task 19 implements SGD selection, opt-in, revision, device/memory/path guards and strict checkpoint settings; tiny-fixture arithmetic and gradients pass. These do not establish full-model fit. The JSON never enables training by itself.
2. **Scientific gate:** freeze the pilot/control schedule, matched baseline settings, metrics, evaluator and available reference-log pins. Confirm target knowledge. Record deviations from the canonical 10-epoch CUDA/AdamW study; do not revise its historical profile to match this pilot.
3. **Read-only gate:** pass the existing FP32 physical-Mac preflight after reclaiming enough memory. Its 20 GiB load threshold and 6 GiB continuing reserve remain unchanged; passing it alone is insufficient for training. It has not yet run with full weights.
4. **Training-memory gate:** for the proposed SGD pilot require a fresh conservative availability lower bound of **at least 32 GiB before load**, system memory free percentage at least 20%, and at least 6 GiB available throughout. The 32 GiB requirement rounds up `9.21 persistent + 12 workspace + 4 uncertainty + 6 free reserve = 31.21 GiB`; it is an implemented but full-model-unvalidated guardrail, not a guarantee. The earlier 17.4 GiB reading fails it. Do not lower guards or disable allocator limits to force a run.
5. **No-update rehearsal gate:** in a later separately authorized task, measure the actual full-model backward working set without stepping an optimizer; verify finite gradients, frozen inputs/original cache, checkpoint recomputation and actual device. Stop on unknown telemetry, yellow/red Activity Monitor pressure, rapid swap growth, OOM, nonfinite values or loss disagreement. Include load and save transients and avoid counting shared RSS/Metal memory twice.
6. **Explicit update authorization:** only after the above evidence is reviewed should one monitored optimizer step be enabled. Its passing status is computational, not empirical forgetting. No cloud resource or paid escalation is a default fallback. If free memory cannot reach the gates, stop and explicitly decide whether to redesign the study as LoRA behavioral adaptation.
